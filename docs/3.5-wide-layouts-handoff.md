# 3.5 Wide Layouts — Design Handoff for Claude Code

_Companion to `docs/3.5-duo-modernization-plan.md`. That plan covers the
platform upgrade and resize safety (Phases 1–3). This doc is the **approved
visual direction for Phase 4** — what the expanded layouts should look like.
Neal reviewed the mockups and likes this direction._

Mockups (Neal's Design canvas, "Sober Dailies Wide Layouts"):
https://claude.ai/artifact/4iZYAnfCWscdE7fztjKxFa

> Neal has no coding background. Explain trade-offs in plain language, and
> follow `PROJECT_RULES.md` (no version/build-number changes, no `eas.json`
> edits without explaining, managed workflow, no `expo prebuild`).

---

## The one idea

**Wide screens get a second pane, not bigger tiles.** On compact widths the
app stays exactly as it is today. When there is room, a list stays on the
left and the thing you picked opens beside it — so the user never has to
"go back" to keep moving through their day.

Decide by **available width** (the plan's `compact / medium / expanded`
modes), never by device name, `Platform.isPad`, or orientation. The foldable
iPhone's real inner-display size isn't confirmed; the mockups assume a wide,
roughly 900×640pt canvas (per leaks) and iPad landscape at 1194×834pt. Pick
real thresholds from resize testing.

## Shared building blocks (build these first)

1. **`useLayoutMode()` hook** — returns `compact | medium | expanded` from live
   window width (and container width where it matters). One place, used by
   every screen.
2. **Navigation rail** (expanded only) — replaces `FloatingTabBar` with a slim
   vertical rail on the left edge (~76pt): Today · Tools · Literature ·
   Journey, icon + small label, selected item gets a soft tinted pill
   (teal-100 bg, teal-700 text). The Settings gear moves to the bottom of the
   rail. Compact keeps the floating bottom bar untouched. Decide where
   `GlobalSponsorFab` lives in expanded mode (rail bottom, above Settings, is
   the suggestion).
3. **Sidebar** (iPad-size expanded) — a wider version of the rail (~248pt)
   with the app name, the four destinations, a contextual group under them
   (e.g. "Library" on Literature: Big Book · Twelve and Twelve · Meeting
   Readings · Prayers), and a small sober-days summary card at the bottom.
   Rail vs. sidebar can be the `medium` vs `expanded` split — confirm in testing.
4. **List-detail container** — a reusable two-pane layout: fixed-width list
   (~330pt) + flexible detail pane, hairline divider between (`border` token).
   Selection lives in state so it **survives fold/unfold** — unfolding opens
   the detail pane on whatever the user had open; folding back returns to
   the pushed detail screen (or the list), never a reset.
5. **Reading-width cap** — reading text maxes out around 560–620pt wide with
   generous side padding, even inside a wide detail pane.

Use existing tokens from `constants/designTokens.ts` (Steel Navy theme: oat
background `#FAF6EF`, white cards, `border` `#E8E4DA`, family colors teal /
steel / periwinkle / terracotta; Archivo display + Inter body). Don't add new
hard-coded hexes. Small grey labels must use `ink2`, not `ink3`, for contrast.

## Screen 1 — Today (foldable open)

Three columns: **rail | dailies list | reading pane**.

- **Middle column (~330pt):** the existing Today header ("Today" + date, gift
  + gear move to the rail/header as appropriate), a compact sober-days card,
  then the existing dailies sections and rows (coin + label + check circle).
  The selected daily row gets a white fill and a 1.5pt accent outline.
- **Right pane:** whatever daily is selected renders here instead of being
  pushed as a new screen. For Daily Reflection: eyebrow
  ("Daily Reflections · November 4"), serif title, quoted passage in a soft
  teal-tinted block, body text at reading width. Bottom action row:
  **Mark done** (filled accent pill), **Journal about this** (outline pill),
  and a right-aligned **"Next: [next daily] →"** link that selects the next
  unchecked daily.
- Default selection on open: first unchecked daily of the current section.
- Dailies that are actions, not content (e.g. "Call my sponsor"), keep their
  current behavior — they don't need a pane.
- Editing dailies (`DailiesEditor`) can stay single-column in the middle pane.

Mockup used a serif (Source Serif 4) for reading text. That's a **proposal**,
not existing app styling — ask Neal before adding a font.

## Screen 2 — Big Book as a two-page spread (foldable open)

The unfolded phone is a book, so show the book that way.

- **Top bar:** back to Literature, book title + "Chapter N · Title",
  then Search, "Aa" text size (existing `ReadingSizeSheet`), Bookmark.
- **Body:** two pages side by side on a warm paper sheet, with a soft
  shadow "crease" down the middle (subtle gradient, decorative only).
  Book page numbers at the bottom of each page.
- Existing **highlights and notes render on the page** (already the 3.0
  direction — no bottom sheets); in the spread, a note can float as a small
  card beside its highlighted passage.
- **Bottom bar:** prev / next spread buttons, a thin progress bar, and
  "pp. 58–59 of N".
- Folding/unfolding must keep the reading position (left page of the spread
  ↔ current page in single-page mode).

**Implementation question to investigate and explain to Neal before
building:** the Big Book currently renders through `PdfReader`
(react-native-pdf) and/or the `bigbook-v2` components. A true two-page
spread may mean two PDF views side by side, or a two-column text layout if
the HTML/text reader is used. Recommend the simplest path. Note `PdfReader`
currently unlocks rotation and re-locks portrait on close — that needs to
fit with the plan's Phase 2 removal of the global portrait lock.

## Screen 3 — Literature on iPad landscape

Three columns: **sidebar | chapter list | reader**.

- **Chapter list (~330pt, white):** "Big Book" title, a search field, then
  chapters as rows: number · title · starting page. Selected chapter gets a
  light steel tint and a 3pt accent bar on its left edge.
- **Reader:** small top bar with "Aa" and an **"Ask AI Sponsor about this"**
  pill (opens Sponsor chat with the chapter as context — new idea, confirm
  scope with Neal). Chapter eyebrow, large serif title, body at reading
  width, highlights shown inline.
- Same pattern applies to Twelve and Twelve and Meeting Readings.

## Applying the pattern elsewhere

Same list-left / detail-right approach, built on the shared container:

- **Tools:** tool grid on the left, the opened tool on the right.
- **Journey:** entries list left, selected entry or editor right
  (preserve unsaved text across layout changes).
- **Speakers / Meetings:** list left, detail (and the player) right.
- **AI Sponsor chat:** centered, width-capped conversation. Possible later
  idea: chat docked beside the reading pane on the foldable.

## Out of scope / don't change

- Compact (normal phone) layouts — no visual changes.
- Version numbers, build numbers, `eas.json`, managed workflow.
- Copyrighted reading text: mockups used placeholders; real content comes
  from the app's existing sources as it does today.

## Suggested build order

1. `useLayoutMode()` + list-detail container + reading-width cap.
2. Navigation rail (expanded) with fold/unfold state preserved.
3. Today two-pane.
4. Literature three-column (iPad) and list-detail (foldable).
5. Big Book spread (after the rendering question is answered).
6. Tools, Journey, Speakers, Meetings.

Test each step with live resizing (Xcode resizable previews / iPad Stage
Manager) before moving on — see the plan's Phase 6 scenarios.
